# Make a host in Go, step 2: frames and the budget

A Terse32 program runs at the same speed on every host. Time comes in frames, 60 a second, and in each frame a program can do a fixed amount of work: 125,000 units. This step adds the file `frames.go` to the package of step 1: the frame loop and the System device's first calls.

## The frame loop

```go from examples/host/go/machine/frames.go
const FrameBudget = 125000

const (
    Running = iota
    Exited
    Faulted
)

type Machine struct {
    *CPU
    Budget   int64
    Frame    uint32
    Stopped  byte
    ExitCode byte
    Fault    *Fault
    Devices  func(slot, fn uint32) (result uint32, charge int64)
}
```

`Machine` is the processor of step 1 with what the frame loop keeps: the budget, the frame counter, and how the machine stopped. `Devices` is for calls to other devices; it stays empty until step 3.

Slot 1 is the System device. `BaseCharge` is the charge of its calls and of a call the machine does not have; `BadBuffer`, the result when a call's buffer is not where it must be. Its calls are numbered by function:

```go from examples/host/go/machine/frames.go
const (
    System     = 1
    BaseCharge = 4
    BadBuffer  = 0xfffffffe
    eventSize  = 4
)

const (
    waitFrame  = 0
    nextEvent  = 1
    frameCount = 2
    exit       = 6
    copyText   = 10
    maxCopy    = 65536
)
```

```go from examples/host/go/machine/frames.go
func (m *Machine) RunFrame() {
    m.Budget += FrameBudget
    for m.Budget > 0 && m.Stopped == Running {
        cost, ecall, fault := m.Step()
        if fault != nil {
            m.Stopped, m.Fault = Faulted, fault
            break
        }
        m.Budget -= cost
        if !ecall {
            continue
        }
        slot, fn := m.X[A7]>>8, m.X[A7]&0xff
        result, charge := uint32(UnknownCall), int64(BaseCharge)
        if slot == System {
            result, charge = m.system(fn)
        } else if m.Devices != nil {
            result, charge = m.Devices(slot, fn)
        }
        m.X[A0] = result
        m.Budget -= charge
        if slot == System && fn == waitFrame {
            break
        }
    }
    m.Budget = min(m.Budget, 0)
    m.Frame++
}
```

In order:

- The frame adds 125,000 to the budget and runs instructions while the budget is above zero. Each costs what `Step` said: 1 if fetched from ROM, 4 from RAM.
- An instruction that starts with budget left always runs to its end, so the budget can end below zero. That debt is carried into the next frame: the carry rule. What is left above zero is dropped (`min(m.Budget, 0)`). When the budget runs out the program is simply paused, and the next frame goes on with its next instruction.
- An `ecall` costs its own 1 (or 4) plus the call's charge, which `system` returns with the result: 4 for a call of the System device (slot 1) and for a call the machine does not have, more for `copy`.
- `wait_frame` ends the frame early: the program has finished this frame's work.
- A fault or `exit` stops the machine. The frame still counts.

## Five calls

```go from examples/host/go/machine/frames.go
func (m *Machine) system(fn uint32) (uint32, int64) {
    switch fn {
    case waitFrame:
        return m.Frame + 1, BaseCharge
    case nextEvent:
        if m.Memory(m.X[A0], eventSize, true) == nil {
            return BadBuffer, BaseCharge
        }
        return 0, BaseCharge
    case frameCount:
        return m.Frame, BaseCharge
    case exit:
        m.Stopped, m.ExitCode = Exited, byte(m.X[A0])
        return 0, BaseCharge
    case copyText:
        // No clipboard: check, charge, drop.
        n := m.X[A1]
        text := m.Memory(m.X[A0], n, false)
        if n > maxCopy || (n > 0 && text == nil) {
            return BadBuffer, BaseCharge
        }
        return 0, BaseCharge + int64(n+3)/4
    }
    return UnknownCall, BaseCharge
}
```

- `100h`, `wait_frame`: returns the number of the frame in which the program goes on, one more than the counter.
- `101h`, `next_event`: the next input event. This host has no input, so the queue is always empty: check that the 4 bytes at `a0` are in RAM (else `FFFF_FFFEh`) and return 0. `hello`, in the next step, calls it every frame and never waits for the next frame without it.
- `102h`, `frame_count`: the frame counter, N all through frame N.
- `106h`, `exit`: the machine stops with exit code `a0` & `FFh`. Like every call it writes its result, 0, to `a0`.
- `10Ah`, `copy`: text for the user's clipboard, `a1` bytes at `a0`. This host has no clipboard, so it drops the text: check that the bytes lie wholly in ROM or wholly in RAM and that there are at most 65,536 (else `FFFF_FFFEh`), charge 1 more per 4 bytes, and return 0. (A host with a clipboard takes the text only in a frame in which the program read the user's copy key, Enter or a pointer press.)

## The program

```go from examples/host/go/step2/main.go
package main

import (
    "fmt"
    "os"
    "strconv"

    "host/machine"
)

func main() {
    file, err := os.ReadFile(os.Args[1])
    if err != nil {
        fmt.Fprintln(os.Stderr, err)
        os.Exit(2)
    }
    frames, _ := strconv.Atoi(os.Args[2])
    cpu, _, err := machine.Load(file)
    if err != nil {
        fmt.Fprintln(os.Stderr, err)
        os.Exit(2)
    }
    m := &machine.Machine{CPU: cpu}
    for m.Stopped == machine.Running && int(m.Frame) < frames {
        m.RunFrame()
    }
    if m.Fault != nil {
        fmt.Fprintln(os.Stderr, m.Fault)
        os.Exit(1)
    }
    os.Exit(int(m.ExitCode))
}
```

It takes the program and the most frames to run.

## Run it

This program calls `frame_count` 100,000 times, then waits for the next frame and exits with what `wait_frame` returned:

```
_start: li   t0, 100000
        li   a7, 0x102      # frame_count
1:      ecall
        addi t0, t0, -1
        bnez t0, 1b
        li   a7, 0x100      # wait_frame
        ecall
        li   a7, 0x106      # exit with its result
        ecall
```

From `examples/host/go`, after `go build -o bin/ ./...`:

```
xxd -r -p > frames.terse <<EOF
544552530001240000010000000000006672616d657300
000000000000000000e1629382026a9308201073000000
fd12e39d02fe93080010730000009308601073000000
EOF
bin/step2 frames.terse 10
echo $?
```

prints `6`, as `terse run frames.terse --frames 10` does. Each pass of the loop costs 7 units: the `ecall` 1 + 4, the other two instructions 1 each. 100,000 passes are 700,000 units, so the loop ends in frame 5 (frames 0 to 4 give 625,000), `wait_frame` returns 6, and the program exits in frame 6. A host that says 3 does not charge calls; 5, its `wait_frame` returns the counter instead of one more; 1, it has no budget at all. Step 1's program says 255: it has no `frame_count`, so the last call returns `FFFF_FFFFh`.
