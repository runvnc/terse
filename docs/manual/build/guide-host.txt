# Make a host

A host is the program that runs Terse32 machines: it reads a program file, runs its instructions, and gives it its devices. `terse-host` is one; you can write another, in any language, and check it against this one exactly. This page builds the smallest useful host, one that runs programs on the text grid, in four small steps, checked along the way with programs from the Tersenet sources.

## Step 1: load and run

A program file starts with a 32-byte header: `TERS`, two bytes that are 0 and 1, the program's length (3 bytes, least significant first), its memory in 8 KiB pages (1 byte), the number of devices (1 byte), 5 zero bytes and a 16-byte title. Two bytes per device follow, then the program's bytes.

Put the program at address `0001_0000h` (that is its read-only memory) and zeroed RAM of the size asked at `0010_0000h`. Start at the program's first byte, with the stack pointer at the end of RAM and every other register 0.

The processor is 32-bit RISC-V with the multiply and compressed instruction extensions (RV32IMC), in user mode only: no interrupts, no special registers. A misaligned load or store, an access outside both memories, or an instruction the machine does not have (`ebreak` and the CSR instructions among them) stops it with a fault.

## Step 2: frames and calls

Time comes in frames, 60 a second. Each frame, add 125,000 to the machine's budget and run instructions while it is above zero: each instruction costs 1 (or 4, when it runs from RAM). What is left over below zero is carried into the next frame; what is left above zero is dropped.

A program talks to its devices with the `ecall` instruction: register `a7` holds the call's number, `a0` to `a5` its arguments, and the result goes back in `a0`. Three calls get the first program running:

- `100h`, `wait_frame`: the program is done for this frame; continue it in the next.
- `106h`, `exit`: the program has finished.
- `200h`, the terminal's `write`: put the text at `a0`, `a1` bytes of it, on the 80 by 30 grid.

Return `FFFF_FFFFh` for every call you do not have yet. With these, `programs/hello/hello.terse` prints its text. Compare with what the reference shows:

```
terse run programs/hello/hello.terse --frames 30 --dump
```

Each call also costs budget. The exact charges matter for matching the reference to the last unit, not for getting this far: they are in [Charges and limits](terse:0cd6940cd27ae344118a79142e415ac92d9df31c5938bdee4e8ef2249cdd8620).

## Step 3: the rest of the program profile

Add the rest of the terminal (cursor, colours, cells), then the system calls and events (keys, text, the pointer), then the 2D vector display. That is 25 calls in all, the whole program profile: SPEC.md section "What a minimal host implements" lists them, and every program built with `terse build` runs on it. `hello` now echoes what you type.

## Step 4: the conformance program

`programs/conform-program` tests a host from the inside: run it for 200 frames with its scripted input, `conform-program.events`, and it prints one PASS or FAIL line per part of the machine. Your text grid should match the first 30 lines of `expected-screen.txt`, every line PASS (the rest of that file is what it draws on the vector display). The reference's screen:

```
terse run programs/conform-program/conform-program.terse \
    --events programs/conform-program/conform-program.events \
    --frames 200 --dump
```

To prove your host exact, compute the machine's state hash (STATE.md) and compare it with `expected-hashes.txt`, frame by frame.

## Proof it is small

`native/core-c` holds `tcore`, a second Terse32 core written in C from the specifications alone. Its core proper (processor, memory, system device and the BLAKE3 hash) is about 530 lines; it leaves the terminal and the other devices to separate programs, as the next page explains, and with the code that talks to them it is about 1,600 lines. It gives every expected hash of `conform-program`. Its README gives an order to write a core in and the traps on the way.

## What you have now

A host that runs every program written for the program profile, and a way to prove it exact. Next, write one of its devices as a separate program: [Make a device](terse:b88eaad5ea82efe3884f1ff97dd40881cd4d714bb985a63249065c9bef2ac1d1).
