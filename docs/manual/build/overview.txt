# What Terse is

First and foremost, Terse is a way to share information: formatted text,
with diagrams where they help, without the bloat of web browsers
(JavaScript, ads, tracking) and without the centralised control of
websites like Reddit.

Secondly, and completely optionally, Terse can be used to share very
lightweight programs, at most 1 MiB of memory each, that run on a small
isolated virtual machine made for the purpose.

## Sharing information

An article is plain text that reads well as it is, with a few marks for
headings, lists, tables, preformatted text and links. A diagram is
written into the article as path data in the style of SVG, so it is
part of the text and needs no image file. There are no scripts, no
styles and no embedded programs, and an article cannot link to a web
page, only to other Terse articles, feeds and programs.

Authors publish articles in feeds. A feed belongs to a key that its
author holds, not to a website: every entry is signed, so a reader can
check that it came from the author whoever delivered it. Relays store
and pass on feeds and articles. Anyone can run a relay, a feed can be
on several at once, and a reader can follow the same feed through any
of them, so no single site decides what may be published or read.

A reader for all of this is a small program. It needs the network and
the article format and nothing else.

## Sharing programs

A Terse program is a small file of machine code for a simple virtual
computer. The machine is isolated: a program sees only its own memory
and the few devices its host offers, such as a terminal, a vector
display and the content store. It gets a fixed amount of work per
frame, so it cannot slow its host down, and it behaves the same on
every host.

All of this is optional. A host may leave out the machine altogether,
or any device it does not want to build, and still be a complete Terse
reader. Articles never contain programs: they can only link to them.
