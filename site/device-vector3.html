The 3D vector display (device 9)

The 3D vector display draws lines, points and circles placed in a box around the screen, from a display list like the 2D display's. Faces, which draw nothing, hide what is behind them; Surfaces show parts of the program's own screen on panels; in the shell's list, Screens place the screens of the machines it started as panels in the box. The program gives geometry, not a picture: the host projects it onto the screen from an eye it chooses, so it may let the viewer look around the models, and the program cannot observe that choice. As with the 2D display, nothing drawn can be read back.

Getting the device

The display is slot 9, version 0. An image gets it by listing (9, 0) in its header: terse pack ... --device 9:0. Without it every call from 900h to 9FFh returns FFFF_FFFFh and does nothing else; so does a number in that range other than the four below.

Space and the eye

Coordinates are signed 16-bit numbers, little-endian, in sixteenths of a screen unit (V3_UNIT is 16). x and y are as on the screen (x right, y down, (0, 0) the top left, 640 by 480 units); z is depth in the same units: 0 is the glass (the plane of the screen), positive is away from the viewer. The axes are right-handed.

The reference eye is at (320, 240, -960) in screen units. Seen from an eye at (ex, ey, -960), a point (x, y, z) with z > -800 is drawn on the glass at

    x' = ex + (x - ex) * 960 / (960 + z)
    y' = ey + (y - ey) * 960 / (960 + z)

So a point on the glass (z = 0) is drawn exactly where the 2D layers would put it, from any eye; a point behind the glass moves with the eye, one in front of it against the eye. For example, from the reference eye the point (480, 240, 960) is drawn at (400, 240). A host may move the eye sideways and up or down by up to 160 units on each axis from the reference eye, at its own discretion (for example following the viewer's pointer or head); the eye's distance from the glass, and the glass, stay fixed. The program is not told where the eye is.

  • submit copies a1 bytes from a0 into the device, replacing the previous list, and returns 0. It is rejected, returning 1 and keeping the previous list, if the length is 0 or more than 16,384 (V3_MAX_LIST) or any part of the range is outside RAM (a list in ROM included).
  • clear empties the list.
  • style (0 clean, 1 phosphor) and persistence (0 to 255) set the display style and persistence described for the 2D display, returning 1 and changing nothing for a value out of range. They are one setting with device 3's: whichever device sets them, both displays and the whole screen are shown that way. A machine whose image lists device 9 and not device 3 has the setting too (device 3's calls stay absent).

After reset the list is empty, the style is clean and the persistence 160. The list the device holds at the end of a frame is the one the host shows for that frame. Nothing of device 9 is filled, so the 2D display's fill mode does not apply.

The display list

A list is a sequence of commands, each one opcode byte followed by its operands. A point x, y, z is three signed 16-bit values (6 bytes). Drawing state at the start of a list: colour opaque white (255, 255, 255, 255), width 16, the identity transform, no saved transforms, current point (0, 0, 0).

Details of the operands: the width is the same on the screen at any depth, 0 counts as 1 and more than 255 as 255. The axis is 0 x, 1 y, 2 z; the angle is unsigned, in 1/65,536 of a turn (V3_TURN is 65,536). The scale is 8.8 fixed point: 256 is 1 (V3_SCALE_ONE). A face's n is 3 or 4, so a Face is 20 or 26 bytes with its opcode. A Screen is 4 bytes, a Surface 11. The C builders are v3_end, v3_colour, v3_width, v3_move, v3_line, v3_point, v3_circle, v3_push, v3_pop, v3_translate, v3_rotate, v3_scale, v3_face3, v3_face4, v3_screen and v3_surface, appending at the buffer given to v3_begin.

Transforms

A point p given to Move, Line or Face is drawn at M(p), where M is the transform in force, with p and every translation in screen units (sixteenths divided by 16). Translate t, Rotate R and Scale s replace M by M o T(t), M o R and M o S(s): each applies to coordinates given after it, before the transforms given earlier, as in ordinary matrix-stack graphics. So "Translate (100, 0, 0), Rotate z a quarter turn, Move (10, 0, 0)" puts the current point at (100, 10, 0).

A positive angle about x turns y towards z, about y turns z towards x, and about z turns x towards y (clockwise as seen on the screen):

Axis(x, y, z) goes to
x(x, y cos a - z sin a, y sin a + z cos a)
y(x cos a + z sin a, y, -x sin a + z cos a)
z(x cos a - y sin a, x sin a + y cos a, z)

The current point is kept as Move or Line placed it, with M applied, so a later transform does not move it. A Line after a Push, a Translate and a Pop starts where the Move put it. Circle, Point and the transform commands leave the current point unchanged.

A circle of radius r (in sixteenths) about the current point c is the closed curve c + L(r cos f, r sin f, 0) / 16, where L is M without its translation: it lies in the plane of M's x and y axes and is scaled with it. It is drawn as the 64 chords between the points at f = k/64 of a turn, k = 0 to 63, joined without ends of their own. A circle of radius 0 is 64 chords of length 0: it counts 64 segments and draws nothing. To draw a circle about a transform's origin, Move to (0, 0, 0) first.

Lines and points use the current width and have round ends (a Point is the dot a line of length 0 draws). They are drawn in list order, each over the earlier ones, blended by opacity. A near line does not cover a far one: only faces hide.

The stack holds up to 8 transforms. Push saves only the transform, not the colour, the width or the current point.

The list ends at an End, at the end of the submitted bytes, at an unknown opcode (0Fh and up), at a command whose operands are cut off, at a Rotate whose axis is above 2, at a Face whose n is not 3 or 4, at a Screen whose handle is 0 or above 8, at a Push with 8 transforms saved, or at a Pop with none. Commands before that point are drawn.

Faces

A face is a flat polygon that gives off no light but hides the lines, points and circles behind it. Its corners are transformed as Move's point is; the current point is not changed. A face of 3 corners is the triangle they make; one of 4 corners is the two triangles of corners 0, 1, 2 and 0, 2, 3 (so it need not be flat or convex). Both sides hide alike. A list without faces draws exactly as it would if faces did not exist.

Seen from the eye in use, a point of a line, point or circle is hidden if the straight segment from the eye to it passes through one of a face's triangles and the point lies more than 2 sixteenths (1/8 unit) beyond the triangle's plane, measured perpendicular to the plane, on the side away from the eye. So a line in a face's plane, along its edge or ending on it is not hidden by that face, and a solid's edges given with the same corners as its faces are drawn. A face hides whatever is behind it wherever the face is in the list, before or after it. A triangle with no area, or seen edge on, hides nothing. Faces do not hide one another and draw nothing, so no line is drawn where two faces cross unless the list draws one.

A line, and each chord of a circle, is drawn as its pieces that are not hidden. Each piece keeps the depth cue that part of the whole line has. An end where a piece was cut is a butt end; the line's own ends keep their own. A piece with a cut end that is shorter than 1/2 unit on the glass is not drawn, unless the whole line is that short; the whole line is measured on the glass, from the eye in use, after the cut at the near plane and before clipping to the screen. A point is drawn or hidden whole.

Screens

A Screen is a flat panel w/16 units wide and 3/4 of that high, centred on the transform's origin in its xy plane. With w in sixteenths and M the transform in force, its corners are

    top left      M(-w/32, -3w/128, 0)
    top right     M( w/32, -3w/128, 0)
    bottom right  M( w/32,  3w/128, 0)
    bottom left   M(-w/32,  3w/128, 0)

so it is scaled, turned and moved with the transform. With the identity it lies like the glass: its top edge along x, its left edge down along y, its front towards the viewer. It does not change the current point. With a = top right - top left and b = bottom left - top left, the panel is seen from behind from an eye on the side of its plane that a x b points to (or in its plane); otherwise its front is seen.

A Screen is in effect only in the list of the shell of a system (the machine with device 8), only if it is the first Screen of its handle in the list, the handle's machine has a picture and the handle's rectangle shows none. Any other Screen is decoded and does nothing: it draws nothing, hides nothing and is not counted. A Screen in effect is shown as a panel and hides lines, points and circles exactly as a Face of its four corners does; one of width 0 has no area and hides nothing. How panels are drawn and take the pointer, and how the shell's face flies one flat onto the glass, is in screens, panels and input.

Caps, presentation and state

Where lines are cut at the near plane, how much one list may draw, how the display is shown and what it charges and keeps in the machine's state are in caps, presentation and state.

Example

A square that turns about its vertical axis, in front of a circle it partly hides:

#include "terse.h"

#define U V3_UNIT
static uint8_t list[256];
static const int16_t sq[4][3] = {
    {-60 * U, -60 * U, 0}, {60 * U, -60 * U, 0},
    {60 * U, 60 * U, 0}, {-60 * U, 60 * U, 0},
};

int main(void)
{
    for (uint16_t a = 0;; a += 256) {
        v3_begin(list);
        v3_push();
        v3_translate(320 * U, 240 * U, 0);
        v3_move(0, 0, 200 * U);         /* behind the glass */
        v3_colour(255, 120, 0, 255);
        v3_circle(100 * U);
        v3_rotate(V3_AXIS_Y, a);
        v3_face4(sq[0], sq[1], sq[2], sq[3]);
        v3_colour(80, 220, 255, 255);
        v3_width(24);
        v3_move(sq[3][0], sq[3][1], sq[3][2]);
        for (int i = 0; i < 4; i++)
            v3_line(sq[i][0], sq[i][1], sq[i][2]);
        v3_pop();
        v3_end();
        v3_submit_list(list);           /* VEC_DONE */
        terse_wait_frame();
    }
}

The list is 98 bytes, so a submit costs 4 + 25 units. It counts 68 segments and 1 face. The square's edges share its face's corners, so they are drawn; the circle is hidden where the square covers it, as the eye in use sees it. Build the image with --device 9:0 (and --device 2:0 for text).
