The reference host's look

This page describes how one host, the reference (terse-host, and terse-bus with the reference drivers), chooses to draw. None of it is a requirement. The specification says what every host must draw: for the phosphor style, a real or simulated vector display with a black screen, filled shapes and the page's figures as outlines, and text as legible as in the clean style (see the 2D vector display). How it looks beyond that is each host's choice: a host that draws plain lines in the given colours on black conforms, and so does one with a real vector monitor. A program may be written with the reference's look in mind, but its picture should not depend on it. The machine is the same, hash for hash, whatever the look; only the picture differs.

The phosphor style

The reference simulates an arcade vector monitor with the renderer of MAME's vector monitors (--look mame, the default): a sharp beam about a pixel wide whatever the line's stated width, light that adds up where lines cross or meet (so a line drawn twice is brighter on this host), a faint glow, and a phosphor that fades within a frame. The GPU renderer runs MAME's passes on the GPU; the software renderer computes the same passes on the CPU.

The terminal's text is drawn by the beam in a vector font. --font-strokes chooses it: arcade (the default, a vector monitor's character generator), hershey (Hershey Roman Simplex), drafting, or off (the glyphs as light). A character the stroke font does not draw, and an article's text, are drawn as light in their colours.

--look classic gives the earlier look: a softer beam on a wide glow, with an afterglow whose tail follows the program's persistence and a smear behind moving shapes. --tube p31|amber|vectrex makes the colours a monochrome tube's, --vignette darkens the glass towards its edges, and --no-trails clears what lingers every frame. The look's options can be kept as lines in the file look of Tersenet's settings folder (look classic, font-strokes drafting); the command line wins.

The 3D display

The 3D lines, points and circles are drawn by the same beam. Light dims with depth as the specification's depth cue says. In the classic look, the beam dwells at line ends and points, with extra light there, but not where a circle's chords join or where a face cut a line.

The eye moves with the pointer (parallax): the picture's centre is the reference eye, an edge the full 160 units the specification allows, smoothed over a few frames. Over a machine that draws in 3D itself the eye rests, so that what you point at stays where the program drew it. --parallax off keeps it still, and --eye <dx>,<dy> places it for screenshots.

Shedding the look

The look is optional work, so the reference drops it before it lets a frame be late. It sheds in steps: in the default look, 1 draws the phosphor at most 720 lines high, 2 at most 480, 3 also without the bloom; in the classic look, 1 drops the smear, 2 the glow, 3 draws plain lines. A frame whose lists draw a lot of ink is shed by the ink alone, so screenshots are the same on every run; in a window it also sheds one level more after 3 frames in a row that took longer than a frame to draw. --no-shed keeps the whole look. A device driver with a look of its own may be told the same level; one that ignores it is still a correct driver.

The shell

The shell's layouts (master and stack, grid, the gallery of machines on a turning ring, zoom) are the shell program's own drawing, not the host's: another shell may lay its machines out any way it likes. See Using the shell.
